`html-schema` holds the plain HTML parts of an item body that have no node or mark in
`prosemirror-schema-basic`: ProseMirror node and mark specs, or fragments to spread over one. Both
schema paths use the same definitions — `createQtiSchema()` in `@citolab/prose-qti` and
`defineBasicExtension()` in `@citolab/prose-extensions/prosekit` — so an item keeps the same markup
whichever one loads it.

Plain ProseMirror only: importing it does not need `prosekit`.

## Install

```bash
pnpm add @citolab/prose-extensions
```

## Global attributes

`class`, `id`, `lang` and `xml:lang` are the attributes QTI 3 gives every content element. Without
an attribute to hold them, ProseMirror's parser drops them on load. `withGlobalAttrs(spec)` returns a
copy of a node or mark spec that keeps them; `withGlobalAttrsOn(specs)` does that for every entry of
a `nodes` or `marks` object that `GLOBAL_ATTR_NODES` / `GLOBAL_ATTR_MARKS` names:

```ts
import { marks as basicMarks, nodes as basicNodes } from 'prosemirror-schema-basic';
import { spanMarkSpec, withGlobalAttrsOn } from '@citolab/prose-extensions/html-schema';

const nodes = withGlobalAttrsOn({ ...basicNodes });
const marks = withGlobalAttrsOn({ link: basicMarks.link, span: spanMarkSpec, ...basicMarks });
```

- Every parse rule keeps its own match and attributes (a heading keeps its `level`), and the spec's
  `toDOM` still decides the element.
- `null` means "no attribute": an element without them serialises as before.
- `lang` and `xml:lang` are two attributes (`lang`, `xmlLang`). Each is written back as the attribute
  it was read from; `xml:lang` in the XML namespace, which the browser also reads as the element's
  language in the editor.
- In ProseKit, `defineBasicExtension()` applies the same list. For a node or mark of your own, add
  `defineNodeGlobalAttrs(type)` / `defineMarkGlobalAttrs(type)` from
  `@citolab/prose-extensions/prosekit`. There, `class`, `lang` and `xml:lang` are `splittable`
  (Enter at the end of a block carries them on); `id` is not.

## Spans

`spanMarkSpec` keeps a `<span>` that has a `class`, `id`, `lang` or `xml:lang` — one mark for all
four, so `<span class="qti-underline" xml:lang="fr">` keeps both. It matches those attributes
(`span[class]`, `span[id]`, …), so a bare `<span>` is still unwrapped and
[Schema Gaps](/docs/prosemirror-plugins/schema-gaps/) still reports it. Nested spans stay separate,
and the span is ranked before the other content marks, so it is written outside them.

## Divs

A `<div>` is kept in one of two ways, depending on what it holds:

- **A div of blocks** with a `class`, `id`, `lang` or `xml:lang` is a `div` node (`divNodeSpec`), so
  `<div class="qti-bordered qti-padding-3">` around a question keeps its frame. A bare div of blocks
  carries nothing and is unwrapped, as before.
- **A div of inline content** is a paragraph written as a div. `withDivParagraph(spec, options)`
  gives a paragraph spec a `tag` attribute (`'p'` | `'div'`) and a `div` rule, so `<div>option A</div>`
  comes back as a div instead of a `<p>`.

```ts
import { nodes as basicNodes } from 'prosemirror-schema-basic';
import { divNodeSpec, withDivParagraph } from '@citolab/prose-extensions/html-schema';

const nodes = {
  ...basicNodes,
  paragraph: withDivParagraph(basicNodes.paragraph, { inlineElements: ['my-inline-widget'] }),
  div: divNodeSpec,
};
```

HTML block elements and every custom element make a div a container of blocks, except the custom
elements passed as `inlineElements`. prose-qti passes `QTI_INLINE_ELEMENTS` (text entry, inline
choice, gap, hottext, …), and so does `defineQtiExtension()`; a host that composes
`defineBasicExtension()` with the QTI interactions itself passes `{ inlineElements: QTI_INLINE_ELEMENTS }`.

- A div-paragraph renders as a `<div>`, so it has no paragraph margins in the editor.
- The div node is in the `richtext` group too, so a classed div inside a rubric block is kept.
- Its `class` attribute is required (`null` is allowed), so ProseMirror never uses it to fill empty
  content.

## Unique ids

An id must be unique, but editing copies it: Enter in the middle of a paragraph gives both halves
its attributes, and a pasted copy of a block brings its id along. `createUniqueIdsPlugin()` clears the
id on the copy and keeps it on the original. At the start of a block, where Enter leaves an empty line
in front, the id stays with the text. It only looks at the nodes an edit created, so a loaded item
that already has duplicate ids is left as it is. `defineBasicExtension()` includes it as
`defineUniqueIds()`.

## Phrasing marks

`phrasingMarkSpecs` holds one mark per phrasing element of QTI 3 that `prosemirror-schema-basic`
has no mark for: `b`, `i`, `small`, `big`, `tt`, `abbr`, `acronym`, `cite`, `dfn`, `kbd`, `samp`,
`var`, `q`, `sub`, `sup`, `bdo` and `bdi`. Spread them after the basic marks:

```ts
import { marks as basicMarks } from 'prosemirror-schema-basic';
import { phrasingMarkSpecs } from '@citolab/prose-extensions/html-schema';

const marks = { ...basicMarks, ...phrasingMarkSpecs };
```

- Each mark is named for its tag, reads only that tag and writes it back. Nothing excludes anything,
  so `<sub><sup>x</sup></sub>` keeps both.
- `<b>` and `<i>` are kept as themselves; prosemirror-schema-basic's `strong` and `em` would
  otherwise read them. The semantic paste plugin still turns a pasted `<b>` / `<i>` from another
  application into `strong` / `em`.
- `q` keeps `cite`, `bdo` keeps `dir` and `title`, `bdi` keeps `dir`.
- `u`, `s`, `mark`, `del` and `ins` are not QTI 3 elements and have no mark. `ruby` is left out too.
  Schema Gaps reports all of them.
- ProseKit editors get the same marks, with `code`, from `definePhrasingMarks()` in
  `@citolab/prose-extensions/prosekit`; `defineBasicExtension()` includes it. A host that also adds
  ProseKit's `defineSubscript()` / `defineSuperscript()` has two marks per tag, and the host's take
  the import.

## Table captions

`tableCaptionSpec` is a fragment to spread over a table node spec. It keeps a `<caption>` as the
table's `caption` attribute and writes it back as the table's first child:

```ts
import { tableNodes } from 'prosemirror-tables';
import { tableCaptionSpec } from '@citolab/prose-extensions/html-schema';

const tables = tableNodes({ tableGroup: 'block', cellContent: 'block+', cellAttributes: {} });
const nodes = { ...tables, table: { ...tables.table, ...tableCaptionSpec } };
```

- The caption is an attribute, not a child node: prosemirror-tables reads every child of a table as
  a row.
- Only the caption's text is kept. [Schema Gaps](/docs/prosemirror-plugins/schema-gaps/) reports
  any element inside a caption, such as an `<em>`.
- `columnResizing`'s `TableView` builds the table DOM itself, so an editor that uses it does not show
  the caption while editing. It is still exported.
