`html-schema` holds the plain HTML parts of an item body that have no node or mark in
`prosemirror-schema-basic`: ProseMirror node and mark specs, or fragments to spread over one. Both
schema paths use the same definitions — `createQtiSchema()` in `@citolab/prose-qti` and
`defineBasicExtension()` in `@citolab/prose-extensions/prosekit` — so an item keeps the same markup
whichever one loads it.

Plain ProseMirror only: importing it does not need `prosekit`.

## Install

```bash
pnpm add @citolab/prose-extensions
```

## Phrasing marks

`phrasingMarkSpecs` holds one mark per phrasing element of QTI 3 that `prosemirror-schema-basic`
has no mark for: `b`, `i`, `small`, `big`, `tt`, `abbr`, `acronym`, `cite`, `dfn`, `kbd`, `samp`,
`var`, `q`, `sub`, `sup`, `bdo` and `bdi`. Spread them after the basic marks:

```ts
import { marks as basicMarks } from 'prosemirror-schema-basic';
import { phrasingMarkSpecs } from '@citolab/prose-extensions/html-schema';

const marks = { ...basicMarks, ...phrasingMarkSpecs };
```

- Each mark is named for its tag, reads only that tag and writes it back. Nothing excludes anything,
  so `<sub><sup>x</sup></sub>` keeps both.
- `<b>` and `<i>` are kept as themselves; prosemirror-schema-basic's `strong` and `em` would
  otherwise read them. The semantic paste plugin still turns a pasted `<b>` / `<i>` from another
  application into `strong` / `em`.
- `q` keeps `cite`, `bdo` keeps `dir` and `title`, `bdi` keeps `dir`.
- `u`, `s`, `mark`, `del` and `ins` are not QTI 3 elements and have no mark. `ruby` is left out too.
  Schema Gaps reports all of them.
- ProseKit editors get the same marks, with `code`, from `definePhrasingMarks()` in
  `@citolab/prose-extensions/prosekit`; `defineBasicExtension()` includes it. A host that also adds
  ProseKit's `defineSubscript()` / `defineSuperscript()` has two marks per tag, and the host's take
  the import.

## Table captions

`tableCaptionSpec` is a fragment to spread over a table node spec. It keeps a `<caption>` as the
table's `caption` attribute and writes it back as the table's first child:

```ts
import { tableNodes } from 'prosemirror-tables';
import { tableCaptionSpec } from '@citolab/prose-extensions/html-schema';

const tables = tableNodes({ tableGroup: 'block', cellContent: 'block+', cellAttributes: {} });
const nodes = { ...tables, table: { ...tables.table, ...tableCaptionSpec } };
```

- The caption is an attribute, not a child node: prosemirror-tables reads every child of a table as
  a row.
- Only the caption's text is kept. [Schema Gaps](/docs/prosemirror-plugins/schema-gaps/) reports
  any element inside a caption, such as an `<em>`.
- `columnResizing`'s `TableView` builds the table DOM itself, so an editor that uses it does not show
  the caption while editing. It is still exported.
