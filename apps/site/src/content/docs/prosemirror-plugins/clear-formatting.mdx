title: Clear Formatting
description: Strip marks and flatten structural wrappers back to plain paragraphs within a range.

`clear-formatting` answers one question: *reset this range back to plain text, structurally.* It
strips every mark across a range, dissolves wrapper nodes (`blockquote`, `bullet_list`/`ordered_list`)
by lifting or flattening their content out, and resets every remaining textblock (headings, etc.) to
a plain paragraph.

It knows nothing about QTI or any other vocabulary: it takes a ProseMirror `Transaction` and a
`{ from, to }` range and mutates the transaction in place.

## Install

```bash
pnpm add @citolab/prose-extensions
```

## Usage

```ts
import { clearFormattingInRange } from '@citolab/prose-extensions/clear-formatting';

const tr = state.tr;
const changed = clearFormattingInRange(tr, { from: selection.from, to: selection.to });

if (changed) dispatch(tr);
```

`range` must already be valid for `tr.doc`. Calling this more than once against the same `tr` (one
call per selected sub-range, say) requires mapping each range through `tr.mapping` first and applying
ranges in reverse document order, so an earlier edit never invalidates a not-yet-processed range.

Pass `options` to change what "plain" means for your schema:

```ts
clearFormattingInRange(tr, range, {
  targetTextblockTypeName: 'paragraph', // node type every reset textblock becomes
  wrapperTypeNames: ['blockquote'],     // dissolved by lifting their content out
  listTypeNames: ['bullet_list', 'ordered_list'],
  listItemTypeName: 'list_item',        // the per-entry wrapper inside a list type
});
```

## When to use

Use this for a "clear formatting" toolbar command or keyboard shortcut over a plain ProseMirror
selection. It has no notion of nodes that must be left alone (an embedded interaction, a code block
you want preserved as-is, …) — a caller that needs to protect some subtree excludes it from `range`
itself. `@citolab/prose-qti`'s `clearFormatting` command (`@citolab/prose-qti/commands`) does exactly
that: it splits the selection around any registered interaction node before calling into this
function, so an interaction the selection happens to span is skipped over rather than touched. See
the [TypeScript Integration](/docs/frameworks/vanilla/#toolbar) guide for that command wired into a
toolbar.
