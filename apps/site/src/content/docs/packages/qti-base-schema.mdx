`@citolab/prose-qti/schema` provides `qtiBasicNodes` and `qtiBasicMarks` — a drop-in replacement for importing `prosemirror-schema-basic` directly when you assemble a raw ProseMirror schema for a QTI host — plus the `qtiLayoutDiv` node spec and its lock plugin, covered below. `qtiBasicNodes` and `qtiBasicMarks` are also re-exported from the package root (`@citolab/prose-qti`).

## When to use this

Use this package when you build your ProseMirror `Schema` by hand (see the [TypeScript Integration](/docs/frameworks/vanilla/) guide) rather than assembling extensions through ProseKit. If you already use ProseKit, `defineBasicExtension()` from [`@citolab/prose-extensions/prosekit`](/docs/prosemirror-plugins/#prosekit-marks-and-lists) covers the same ground.

## Why not `prosemirror-schema-basic` directly

- **Image dimensions.** `qtiBasicNodes.image` preserves `width` and `height` attributes on parse and serialize. Plain `prosemirror-schema-basic` drops them, so QTI XML image dimensions are lost on import and re-export.
- **An explicit place to trim the baseline.** `createQtiBasicNodes()` lets a host schema omit optional baseline nodes (for example `blockquote`) explicitly, instead of filtering `prosemirror-schema-basic`'s exports ad hoc in every consumer.

## What it provides

- `qtiBasicNodes` — `prosemirror-schema-basic`'s node specs with the `image` node's `parseDOM`/`toDOM` replaced to round-trip `width`/`height`.
- `qtiBasicMarks` — `prosemirror-schema-basic`'s marks, unchanged, re-exported for a single consistent import path.
- `createQtiBasicNodes(options?: { omitBlockquote?: boolean })` — returns `qtiBasicNodes`, omitting `blockquote` by default (pass `{ omitBlockquote: false }` to keep it).

## Typical usage

```ts
import { Schema } from 'prosemirror-model';
import { qtiBasicNodes, qtiBasicMarks } from '@citolab/prose-qti';
import { qtiChoiceInteractionNodeSpec } from '@citolab/prose-qti/components/choice';

export const appSchema = new Schema({
  marks: qtiBasicMarks,
  nodes: {
    doc:       { content: 'block+', attrs: { identifier: {}, title: {} } },
    paragraph: { ...qtiBasicNodes.paragraph, content: 'inline*', group: 'block richtext' },
    text:      qtiBasicNodes.text,
    image:     qtiBasicNodes.image,

    // QTI interactions
    qtiChoiceInteraction: { ...qtiChoiceInteractionNodeSpec },
  },
});
```

Only the node names you list in the `nodes` object end up in the schema — `qtiBasicNodes` and `createQtiBasicNodes()` are both plain lookup objects, not a schema fragment applied automatically. Restate `content`/`group` for each node as your document topology requires, the same as for any other node spec in this repo (see the [TypeScript Integration](/docs/frameworks/vanilla/) guide).

## Layout wrappers: `qtiLayoutDivNodeSpec` and `qtiLayoutDivLockPlugin`

QTI items can arrive with `<div class="qti-layout-row">` / `qti-layout-colN` wrappers, styled by the theme's `@media (width <= 767px)` responsive rule. These are author-written item content, not editor furniture, so the document model for them lives in this package rather than in a host app:

- `qtiLayoutDivNodeSpec` — a single block-level `NodeSpec` shared by both the row and column wrappers (the distinction is carried entirely by the preserved `class` string). It is `isolating` and `selectable: false`, so edits and Backspace/Delete joins don't cross the wrapper boundary and the wrapper itself can't be node-selected.
- `qtiLayoutDivLockPlugin` — a ProseMirror plugin that rejects any transaction changing how many `qtiLayoutDiv` nodes the document contains. Add it to your plugin list to opt in:

  ```ts
  import { qtiLayoutDivNodeSpec, qtiLayoutDivLockPlugin } from '@citolab/prose-qti/schema';

  const schema = new Schema({
    nodes: {
      // ...
      qtiLayoutDiv: { ...qtiLayoutDivNodeSpec, content: 'block+', group: 'block' },
    },
  });

  const plugins = [/* ...other plugins */, qtiLayoutDivLockPlugin];
  ```

Without the plugin, `isolating`/`selectable: false` are only advisory — a selection spanning a wrapper can still delete it, and nothing in the editor can recreate one afterward, since layout wrappers only ever arrive via import and no interaction offers a command to author one. The plugin is a separate export rather than something applied automatically, so a host that genuinely wants editable grids can opt out by omitting it.

## Notes

- `blockquote` is omitted by default when using `createQtiBasicNodes()` because QTI item bodies do not model it; use `qtiBasicNodes` directly (or pass `{ omitBlockquote: false }`) if your host schema needs it.
- `qtiBasicMarks` is `prosemirror-schema-basic`'s `marks` object as-is — mark identity is unaffected, so `strong`/`em`/`code`/`link` are unchanged.
